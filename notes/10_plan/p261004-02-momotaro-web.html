目的

「桃太郎」の冒頭（桃から生まれて名付けられるまで）を、ブラウザで動く紙芝居にする。絵・字幕・効果音・読み上げ音声をそろえる。範囲は 計画: 桃太郎を最後までで全編に広げ、作品の名前も「桃太郎（冒頭）」から「桃太郎」に改めた。

音はすべてブラウザの中で作る。効果音と BGM は Web Audio API、読み上げは Web Speech API を使う。音声ファイル・画像ファイル・外部サービスは使わない。

計画 p261004-01 との関係: p261004-01 の段階 1・2 を、この計画で置き換える。p261004-01 で範囲外にしていた BGM・効果音を含め、読み上げは wav ではなくブラウザで行う。承認後、p261004-01 にこの計画へのリンクと変更点を書く。動画化（段階 3）は p261004-01 のまま残す。

台本

昔話のため著作権の制約はない。文は自分で書く。5 場面。

場面絵ナレーション音
1山あいの家と、おじいさん・おばあさんむかしむかし、ある所に、おじいさんとおばあさんが住んでいました。拍子木（始まり）・BGM 開始
2山へ向かうおじいさん、川へ向かうおばあさんおじいさんは山へしばかりに、おばあさんは川へせんたくに行きました。鳥の声
3川で洗濯するおばあさん。上流から大きな桃が揺れながら流れてくるおばあさんが川でせんたくをしていると、川上から大きな桃が、どんぶらこ、どんぶらこと流れてきました。川の水音・どんぶらこの揺れに合わせた音
4家で桃を切ろうとすると、桃が割れて赤ちゃんが出てくるおばあさんは桃を家に持ち帰りました。おじいさんが包丁で切ろうとすると、桃がぱかっと割れて、中から元気な男の赤ちゃんが生まれました。ぱかっ（割れる音）・きらきら
5赤ちゃんを抱く二人桃から生まれたので、二人はこの子を「桃太郎」と名づけました。拍子木（終わり）・BGM 終了

台本は作品の story.js に JavaScript の配列として持ち、<script src> で読み込む。script.json に分けると、ファイルを直接開いたとき（file://）に読み込めないため。

画面と操作

画面

  • 紙芝居の枠（木の舞台風）の中に、場面の絵を SVG で描く。横長 16:9
  • 絵の下に字幕。場面の文を全部出し、読んでいる句に色を付ける。先の文も見えるので、読み上げが無い環境でも字幕だけで読める（15-A。読んでいる文だけを出す 15-B は採らない）
  • 場面の切り替えは、紙を横へ引き抜く動き（紙芝居の「抜き」）にする
  • 場面内の動き: 桃が上下に揺れながら流れる（場面 3）、桃が左右に割れる（場面 4）など、CSS アニメーションで付ける

操作

  • 最初に「はじまり」ボタンを押す。ブラウザは操作なしに音を出せないため、これが必須
  • 自動送り: 読み上げが終わったら、少し間を置いて次の場面へ
  • 手動送り: クリック・矢印キーで前後に移る。移ったら読み上げを止めて、その場面を読み直す
  • 音・読み上げのオン/オフを切り替えるボタン（字幕だけで読めるように）

音と読み上げ

効果音と BGM（Web Audio API）

  • サンプル notes/samples/sound-webaudio.html の作り方（波形をその場で計算）を使う
  • 拍子木: 短く高い音を 2 回。鳥の声: 高さを素早く上下させる音。水音: ノイズをフィルターに通して揺らす。ぱかっ: 短いノイズ。きらきら: 高い音の連続
  • BGM: 和風に聞こえるよう、ペンタトニック（ド・レ・ミ・ソ・ラ）の短い旋律を繰り返す。読み上げ中は音量を下げる

読み上げ（Web Speech API）

  • サンプル notes/samples/speech-webspeech.html の作り方を使う
  • 日本語で、内蔵の声（PC・スマホの中で動く。localService が true）を優先して選ぶ。無ければネットの声を使い、それも無ければ字幕だけで進める
  • 読み上げの終わり（onend）で次の場面へ送る
  • 読んでいる文字に色を付ける（onboundary）。色の境目は 1 語ずつではなく、読んでいる句の「、」「。」まで進めて、声が次の句に入るまで待つ。読み用の文（read）を使った文は、字幕と文字の位置がずれるため、何番目の句を読んでいるかで字幕の句に対応させる（16-A。読みを変えるのは語だけで、「、」「。」の数は変わらない）。位置が届かない声では文単位の表示にする
  • 読み上げを始めるたびに、先頭の音が削れる（「おじいさん」の「お」が短く聞こえる）。声を変えても、文頭に「、」を置いても直らず、文頭に「っ」を置くと最初の音まで聞こえた。読み上げる文の先頭に毎回「っ」を足す（字幕には出さない）。削れる原因が再生機器かエンジンかは分かっていない
読みの誤り: 音声合成は「川上」「包丁」などを読み違えることがある。その場合は、読み上げる文だけをひらがなにする（字幕は漢字のまま）。台本には字幕用と読み用の 2 つの欄を持たせる。

段階ごとに利用者の確認を取ってから次へ進む。

段階 1: 絵と字幕

  • 5 場面の SVG、字幕、場面の切り替え、手動送り
  • 結果: ✅ 済。共通の仕組みは src/engine/kamishibai.css・player.js、作品は src/works/01-momotaro/。tests/momotaro.spec.ts（tools/40_test/run-tests.cmd で実行）で、表紙から 5 場面を送り字幕が台本どおりに変わること、送りのボタンまで 1 画面に収まることを確かめた

段階 2: 読み上げ

  • 「はじまり」ボタン、読み上げ、読み終わりでの自動送り、読み違いの直し
  • 結果: ✅ 済。読み上げは src/engine/speech.js。文ごとに、先頭に「っ」を足して読む。読んでいる文に色を付け、位置が届く声なら、読んでいる句の「、」「。」まで色の境目を進める。読み終えて 1.5 秒（場面に入って 5 秒未満なら 5 秒まで）待って次の場面へ送る。日本語の声が無いときは字幕だけで、文字数に応じた時間で送る。使っている声の名前を送りのボタンの下に出す
  • 確認: tests/momotaro.spec.ts では読み上げを差し替えて、自動送り・読む順・先頭の「っ」・句単位の色付け・手で送ったときの読み直し・声が無いときの送りを確かめた。本物の声は利用者が聞き、読み違いは見つからなかったため read は使っていない

段階 2+: 声の切り替え

利用者の要望。送りのボタンの下に出ている声の名前をクリックして、別の声に変える。変えたら、今の場面を頭から新しい声で読み直す。選べるのは日本語の声だけ。4-B・5-A に決まった。一覧はブラウザ標準の選択欄（select）で開く。選んだ声はブラウザの localStorage に残し、残せない・残した声が無くなったときは内蔵の声を優先して選び直す。

結果: ✅ 済。tests/momotaro.spec.ts で、一覧に日本語の声だけが「内蔵」「ネット」の別つきで並ぶこと、選ぶと今の場面を頭から読み直すこと、開き直しても選んだ声で読むこと、残した声が無くなれば内蔵の声に戻ること、一覧で矢印キーを押しても場面が送られないことを確かめた。

一覧の別は、はじめ「PC 内」と書いていたが、iPhone で「Kyoko（PC 内）」と出て合わなかったため、PC にもスマホにも通る「内蔵」に改めた（14-D）。サンプルページ notes/samples/speech-webspeech.html も同じ言い方にした。iPhone では、Safari も Chrome も内蔵の声だけが出て、ネットの声は出ない。

  • 4. 変え方
    • 4-A: クリックするたびに、次の日本語の声に回す。日本語の声は数個（この PC では PC 内の 3 つ）で、回しても手間にならない
    • 4-B: クリックで一覧を開き、選ぶ。「PC 内」「ネット」の別も出す。声が多いブラウザで選びやすい
  • 5. 選んだ声を覚えるか
    • 5-A: 覚える（ブラウザに残し、次に開いたときもその声で読む）
    • 5-B: 覚えない（開くたびに、PC 内の声を優先して選び直す）

段階 2++: 表紙に戻るボタン

利用者の要望。送りのボタン（‹ ›）の左に「⏮」を置き、押すと読み上げを止めて表紙に戻る（13-A。1 場面目に戻る 13-B は採らない）。表紙ではこのボタンを押せない。

結果: ✅ 済。tests/momotaro.spec.ts で、表紙では押せないこと、押すと読み上げを止めて表紙に戻り、表紙では読み上げないことを確かめた。

段階 3: 効果音と BGM

  • 場面ごとの効果音、BGM、読み上げ中の音量下げ、オン/オフ
  • 音はすべて Web Audio API でその場で作る（src/engine/sound.js）。どの場面で何を鳴らすかと BGM の旋律は、作品の story.js に書く
  • BGM: 唱歌「桃太郎」の旋律を全編で繰り返す。13 場面（戦い）だけ速くし、低い音を足す。読み上げ中は音量を下げる（21-A）
  • 効果音: 動物の声も合成で似せて鳴らす（22-A）。1 拍子木、2 鳥の声、3 川の水音とどんぶらこ、4 ぱかっ・きらきら、6 どすん、7 雷、9 ワン、10 キキッ、11 ケーンと羽音、12 波、13 ドカーン、14 きらきら、15 拍子木。15 場面の終わりで BGM を消していく
  • 音を消すボタン: 「音」（効果音と BGM）と「読み上げ」を、別々のボタンで消せる（23-A）。読み上げを消すと、字幕だけで時間をおいて送る
  • 「はじまり」を押したときは、音も読み上げも出す状態で始める。ブラウザは操作の前に音を出せない
  • 結果: 実装は済み。旋律は、ドレミ付きの初級の楽譜（ハ長調・4 分の 4 拍子）の 3〜8 小節目から起こした。tests/momotaro.spec.ts では、sound.js が残す記録（鳴らした音の名前、BGM と音量下げの状態）で、拍子木と BGM の始まり・表紙での停止、場面ごとの効果音、13 場面で BGM が速くなること、読み上げ中の音量下げ、2 つのボタンの動きを確かめた。Playwright の Windows 版 WebKit には Web Audio が無いため、音のテストは Chromium だけで通している
  • 残り: 利用者が聞いて、BGM の旋律と効果音を確かめる
  • 声を選ぶ欄の見出しは「声:」にした。隣の「読み上げ」ボタンと同じ言葉で並ぶと紛らわしいため

確認は Chrome と Edge で行う。PlayWright 共有環境で各場面のスクリーンショットを撮り、絵の崩れを見る。音は利用者が聞いて確かめる。

テストは PlayWright 共有環境の Chromium と WebKit（iPhone の Safari と同じしくみ）で流す（20-A）。スクリーンショットはブラウザごとに tmp/screens/chromium/・tmp/screens/webkit/ に撮る。Firefox は共有環境側で描画のエラーが出るため外している。Edge では確かめていない。

決めること

個別の回答はなく、「作ってみて」の指示を受けて、すべて推奨の A で着手した。変えるときはこの章を直す。

  • 1. 範囲
    • 1-A: 名づけまで（5 場面）。冒頭として切りがよい
    • 1-B: 鬼退治に出発するまで（7〜8 場面）
  • 2. 読み上げ
    • 2-A: Web Speech API。ブラウザだけで完結し、台本を直せばすぐ反映される。声はブラウザ・PC によって変わる
    • 2-B: Windows の音声合成で wav を作り、HTML で再生する。声は固定できるが、台本を直すたびに作り直しが要る
  • 3. 絵の調子
    • 3-A: 太い輪郭と平塗りの、紙芝居らしい単純な絵
    • 3-B: 影・グラデーションを付けた絵本風。手間が倍ほどかかる
