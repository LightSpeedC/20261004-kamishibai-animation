## 1. 目的

[p261010-01](p261010-01-voice-synthesis.md) で、4 声の文ごとの音声を wav で置いた。1 声 5〜12 MB あり、スマホの通信に重い。wav から変換した mp3 を、別の項目として声の一覧に足す。wav は置き換えずに残す。

前提: [p261012-01](p261012-01-voice-storage.md)（一覧の値を `r:key:形式` にし、voice.js に `format` を持たせる）が済んでから実装する。同じファイルを触るため。

## 2. 決まっていること

- mp3 は wav を置き換えず、別の項目として足す（p261010-01 の 38。2026-10-11）
- 表示は `無料: wav➡mp3 1MB: VOICEVOX: ずんだもん` の形。大きさは mp3 の合計（2026-10-11）
- 一覧の値は `r:zundamon:mp3`。wav の `r:zundamon:wav` は変えない（p261012-01）
- mp3 を足したら、既定の声を `r:zundamon:mp3` にする（2026-10-12）
- 変換は共有ツールの `convert-audio`（ffmpeg）で行う

大きさの実測（2026-10-12。`convert-audio` の既定の 64kbps。`tmp/` に変換して測った）:

| 声 | wav | mp3（64kbps） |
|---|---:|---:|
| ずんだもん | 5.9 MB | 1.0 MB |
| 四国めたん | 5.1 MB | 0.9 MB |
| まお | 11.6 MB | 1.1 MB |
| コハク | 12.0 MB | 1.1 MB |

## 3. 決めること

72〜76 はすべて A に決まった（2026-10-12）。64kbps の mp3（ずんだもん 1 場面 1 文目）は利用者が聞き、問題なかった。

### 72. ビットレート

- **72-A（推奨）** 64kbps。1 声 約 1 MB（実測）。語りの声には足りる見込み。聞いて確かめる
- **72-B** 96kbps。約 1.5 倍の大きさ
- **72-C** 128kbps。約 2 倍の大きさ

### 73. 置き場

- **73-A（推奨）** wav と同じフォルダ（`voice/zundamon/s01-1-指紋.mp3`）。同じ文の wav と mp3 が名前で並び、指紋も共通にできる
- **73-B** 形式ごとのフォルダ（`voice/zundamon-mp3/`）

### 74. 変換する場所

- **74-A（推奨）** `make-voice.ts` が、wav を作ったあとに mp3 も作る。wav と同じく、無いものだけを作る。作り直し忘れが起きない
- **74-B** 別のスクリプトにして、手で流す

### 75. 句の終わりの時刻（`ends`）

mp3 は変換で先頭に短い無音が入ることがあり、時刻がずれる可能性がある（未計測）。

- **75-A（推奨）** まず wav と mp3 の長さの差を測る。差が字幕の色の進みに影響しない程度（数十ミリ秒）なら、wav の時刻をそのまま使う
- **75-B** 差を測って、mp3 用の時刻を別に持つ

### 76. 一覧での並び

- **76-A（推奨）** 声ごとに mp3、wav の順（ずんだもん mp3・ずんだもん wav・四国めたん mp3 …）。同じ声が隣に並び、既定（mp3）が先に来る
- **76-B** mp3 の 4 声を先に、wav の 4 声を後に

## 4. 進め方

- p261012-01 の実装が済んでから着手する
- mp3 のためのテストは足さない（利用者の判断。2026-10-12）。確かめるのは、mp3 を再生できること（Chrome と iPhone の Safari）。音質も聞いて確かめる
- 既存のテストのうち、一覧の並び・既定の声・voice.js の中身を見ているものは、mp3 を足した形に合わせて直す

結果: ⚠️ 実装済み・再生の確認待ち（2026-10-12）。`make-voice.ts` が wav の隣に同じ名前の mp3（64kbps）を作り、`voice.js` に声ごとに mp3・wav の順で並べる。4 声 108 本を作り、2 回目は作り直しが 0 本だった。表示は「無料: wav➡mp3 1MB: …」。`recorded.js` は key と形式の組で声を選ぶ形にした（同じ key に 2 つの形式があるため）。wav と mp3 の長さの差は全 108 本で最大 0.3 ミリ秒で、wav の時刻をそのまま使う（75-A）。既存のテストを並びと既定の声に合わせて直し、chromium と webkit で全件が通った（79 件。音のない webkit の 5 件は従来どおり飛ばす）。PC の Chrome では利用者が聞き、問題なかった（2026-10-13）。残りは、公開したあとに iPhone の Safari で鳴ることを確かめること。
